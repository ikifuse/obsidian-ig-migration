# Obsidian IG安全進行

## 原則

必要な専門調査を省略せず、最終判断に必要な情報だけを人間が読める量へ整理する。最終判断はオーナーが行う。一般論で案件を広げず、現在の完走条件と依頼の範囲を基準にする。

同じ規則をSkillへ複製しない。リポジトリ直下の`AGENTS.md`を常に適用し、対象工程は同文書の読み込みルーターから現役workflowと正本を選ぶ。`09_IGC統合/`または`10_Memory_Synapse_DB/`では、対応する子`AGENTS.md`も適用する。

## 依頼を確定する

1. 最新の依頼を、対象、求める結果、許可された操作、停止点の一文に整理する。
2. 作業開始前に`git status --short`を確認し、既存差分と今回の差分を分ける。
3. 「確認」「調査」は、現物を見るだけで終えない。現在の状態、適用ルール、必要な履歴と過去の承認、発生理由、影響をつないで調べる。変更は依頼されていない限り行わない。
4. 「進めて」は、直前に確定した対象と停止点だけに適用する。

## 調査と提案

1. 現役正本、対象コード、成果物、検査結果を必要な範囲で照合する。確認済み事実、推測、提案、未確認を混ぜない。
2. 提案前に、現在の完走条件との関係を`完走必須`、`問題解決に必要`、`任意改善`、`完了後候補`のいずれかへ分類する。
3. オーナーが求めていない任意改善と完了後候補は提案しない。既存の採用事項と矛盾する一般案を出さない。
4. 技術的な十分性は、現物、テスト、履歴からAIが評価する。最終的な採用・変更判断はオーナーが行う。
5. 十分に調査できていない状態で判断を求めない。安全に続けられる調査を終えてから説明する。

## オーナーへの説明

通常は一度に一つの判断だけを、画面一枚程度の日本語で説明する。最初に結論を置き、次だけを示す。

- 何が起きているか
- 放置または採用で何が変わるか
- 現実的な選択肢。結果が実質同じ案はまとめる
- AIの推奨と理由を最大3点
- オーナーが今回判断する一つの内容

専門的な根拠と全調査はAIが完了する。通常回答へ調査過程や全ログを並べず、判断を変え得る根拠だけを示す。詳細はオーナーが求めた場合に提示する。過去の会話、phase名、Gitコマンドまたは専門用語を覚えている前提にしない。

対象workflowが必須表を定める場合も、同じ事実を繰り返さず一つの小さな表へ圧縮する。

## 変更する

1. 承認された対象だけを変更する。複数の合理的解釈で成果物が変わる場合だけ停止する。
2. 変更前の成立部分と対象外を維持し、完走に不要な整理、再設計、リファクタリングを混ぜない。
3. 新しいファイルを作る前に、正式成果物、継続利用する補助ツール、一回限りの補助ツールのどれかへ分類する。
4. 継続利用する補助ツールは既存の`tools/`または対象工程の`scripts/`へ置き、現役手順から参照する。
5. 一回限りの補助ツールは検査終了後、`docs/document-governance.md`に従って退役理由とともに`99_完了済み参考資料/`へ移し、現役差分へ残さない。
6. 変更後に、対象仕様、コード、成果物、対象外の無変更を必要な検査で確認する。

## 差分を監査する

コミット準備前と完了報告前に、Skill同梱の検査を実行する。`--allow`には今回変更を許可されたファイルまたはディレクトリだけを繰り返し指定する。

```bash
node .agents/skills/obsidian-ig-safe-workflow/scripts/audit-change-scope.mjs \
  --allow path/to/approved-file \
  --allow path/to/approved-directory/
```

検査が対象外変更、ルート直下のスクリプト、TypeScript元コード内のPython補助スクリプトを報告したら、コミットせず原因を解消する。検査結果だけで意味上の正しさを代替せず、仕様と実物も確認する。

## Gitと完了

1. ステージ、コミット、pushはオーナーがその操作またはGitHubへ反映する結果を明示した場合だけ行う。
2. `git add -A`と`git add .`を使わない。今回の対象パスだけを明示してステージする。
3. `git diff --cached --name-status`で許可対象との一致を確認し、不一致ならコミットしない。
4. `main`へのpush、merge、Pull Request、タグ、releaseは、対象操作について別の明示許可が必要な場合を各`AGENTS.md`で確認する。
5. 完了報告は、結果、変更したもの、検査結果、変更していないもの、未解決事項だけを短く示す。

## 停止する条件

- オーナーの目的または到達結果を複数に解釈できる。
- 承認範囲外の変更、破壊的操作、外部公開または別工程が必要になる。
- 現役正本を特定できない、または正本と現物の不一致を分類できない。
- 必須検査が不合格、または技術判断を変え得る未確認事項が残る。

停止時も大量の判断材料を渡さない。判明した問題、進められない理由、オーナーが決める一つの内容だけを説明する。

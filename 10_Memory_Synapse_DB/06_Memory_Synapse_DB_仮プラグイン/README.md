# Memory Synapse DB 読み取り専用06 導入・確認説明書

## この06は何か

06は、Obsidian上で大量のMarkdownとWikiリンクを読み取り、Memory Synapse DBの画面と操作が成立するかを確かめるための**読み取り専用技術検証版**です。

> [!WARNING]
> 正式プラグイン08ではありません。Markdownの作成・変更・削除、融合結果や手書き情報の保存、外部通信は行いません。日常利用中のVaultへは入れず、必ず05のサンプルVaultを複製して確認してください。

## `main.js`が短く見える理由

`main.js`は、人が説明書を書くための原稿ではなく、Obsidianが実行するためにTypeScriptから自動生成・圧縮したファイルです。そのため、改行が少なく、非常に短く見えます。

画面の仕様と説明書の根拠は、次の三つです。

- [人が読めるTypeScript元コード](../04_Memory_Synapse_DB_実行コード/TypeScript元コード/04_画面/Obsidian画面.ts)
- [ビルド方法](../04_Memory_Synapse_DB_実行コード/99_ビルド・検証方法.md)
- [承認済みのブラウザー確認内容](../05_Memory_Synapse_DB_サンプル検証キット/ブラウザー確認操作説明書.md)

## プラグインとして必要なファイル

Obsidianが読み込むフォルダーは、次の三ファイルで正しい構成です。

```text
<確認用Vault>/
└── .obsidian/
    └── plugins/
        └── memory-synapse-db/
            ├── main.js
            ├── manifest.json
            └── styles.css
```

このREADMEは利用者向け説明書なので、実行用の`memory-synapse-db/`には入れず、一つ上の06フォルダーに置いています。

`/ikifuse/.obsidian/plugins`という決まった共通場所へ入れるのではありません。**今回Obsidianで開く確認用Vaultの中**にある`.obsidian/plugins/`へ入れます。

## 必要なもの

- デスクトップ版Obsidian 1.5.0以降
- [05のサンプルVault](../05_Memory_Synapse_DB_サンプル検証キット/サンプルVault/)の複製
- [06の実行用三ファイル](memory-synapse-db/)

## 導入手順

### 1. サンプルVaultを複製する

Finderで`サンプルVault`フォルダーを複製し、例として`サンプルVault_06確認用`という名前にします。元のサンプルVaultや日常利用Vaultは使いません。

### 2. `.obsidian/plugins`を開く

1. 複製した確認用VaultをFinderで開く。
2. `.obsidian`が見えない場合は、`Command`＋`Shift`＋`.`を押して隠しファイルを表示する。
3. `.obsidian`の中に`plugins`フォルダーがなければ作る。

### 3. 三ファイルを配置する

06にある`memory-synapse-db`フォルダーを丸ごと、確認用Vaultの`.obsidian/plugins/`へコピーします。

コピー後、次の場所になっていることを確認します。

```text
サンプルVault_06確認用/.obsidian/plugins/memory-synapse-db/
```

その中に`main.js`、`manifest.json`、`styles.css`が一つずつあれば配置完了です。

### 4. Obsidianで有効にする

1. Obsidianの「保管庫としてフォルダーを開く」で、複製した確認用Vaultを開く。
2. Obsidianの`設定`を開く。
3. `コミュニティプラグイン`を開く。
4. 制限モードを解除する必要がある場合は、確認用Vaultに限って解除する。
5. 一覧の`Memory Synapse DB`を有効にする。

一覧に出ない場合は、Obsidianを再読み込みまたは再起動し、三ファイルの配置場所をもう一度確認します。

### 5. Memory Synapse DBを開く

次のどちらかで開きます。

- Obsidian左端のリボンにあるMemory Synapse DBのアイコンを押す。
- `Command`＋`P`でコマンドパレットを開き、`読み取り専用の技術検証版を開く`を実行する。

## 最初の合格確認

次の四点を最初に確認してください。

- [ ] 画面に読み取り専用技術検証版である旨が表示される。
- [ ] 対象ルートが`Instagram_Logs/Synapses`になっている。
- [ ] Mention、Location、Tagのカードを読み込める。
- [ ] 既存の融合単位と種類別代表を確認できる。

対象ルートが異なる場合は、Obsidianの`設定` → `Memory Synapse DB` → `対象ルート`を開きます。05のサンプルVaultでは通常、初期値のままで構いません。

## 06にあるボタン

06の操作結果は、Obsidianを再読み込みまたは再起動するとVaultから読み直されます。Markdownへは保存されません。

| ボタン・操作 | 画面内で起こること |
|---|---|
| `再読込` | Vaultから読み直し、画面内だけの変更を破棄する |
| `元に戻す` | 画面内で行った直前の操作を一回取り消す |
| `初期状態へ戻す` | 現在読み込んでいる状態を基準に画面内変更を戻す |
| 検索欄 | 名前などからカードを探す |
| `全種類` / `Mention` / `Location` / `Tag` | 種類で絞り込む |
| `全状態` / `単独` / `関係管理` / `カテゴリ代表` / `その他の構成カード` | 現在の状態で絞り込む |
| `手書きあり` | 手書き情報があるカードだけに絞る |
| 各`ファイル名.md`のボタン | 対象MarkdownをObsidianのタブで開く |
| カードを別カードへドラッグ | ドロップ先を受け入れる側として融合確認を開く |
| `融合へ追加` | 融合相手を選ぶ画面を開く |
| `手書き` | 個別カードの補足情報を画面内だけで編集する |
| 関連投稿ボタン | 関連する投稿Markdownを開く |
| `関係管理を変更` | 融合関係を管理するカードを画面内で変更する |
| `代表を選択` / `代表を変更` | 種類ごとの表示代表を画面内で選ぶ |
| `分離` | 選択した個別カードを画面内で融合単位から外す |
| `融合を解体` | 融合単位を画面内で解散する |
| `画面内で実行` | 選択内容をファイルへ保存せず、現在の画面セッションだけへ反映する |
| `保存内容を確認` | 手書き内容を確認し、了承した場合だけ画面内へ反映する |
| `キャンセル` | 変更せずに確認画面を閉じる |

05のObsidian風左サイドバーは06へ持ち込まず、実際のObsidian標準ファイル一覧を使います。

## 今回修正した四点

四点は04のTypeScript元コードへ実装し、04から06を再生成しました。06だけを直接手直ししたものではないため、今後同じ通常ビルドを行っても修正内容は残ります。

| 確認番号 | 新しい06で確認する状態 |
|---|---|
| B-04 | 同じ種類のカードが複数ある場合、代表確認の操作を終えるまで`画面内で実行`が有効にならない |
| B-06 | 融合単位同士の既存代表が競合した場合、代表欄が未選択になり、人が選ぶまで確定できない |
| B-18 | 融合、分離、解体、関係管理変更、代表変更、手書き保存の前に、`現在`、`操作後`、`変更するファイル`、`変更しない情報`、`元に戻せるか`を表示する |
| B-19 | 異常がある場合だけ`問題検査`を表示し、解析不能、リンク、多重所属、入れ子、代表を種類別件数と対象ファイルで示す。自動修復しない |

型検査、23件の自動試験、依存境界検査、通常ビルドおよび生成物の安全確認は合格しています。**Obsidian実画面でのB-01〜B-19の合否は、これからこの説明書に沿って確認する段階です。**

## B-01〜B-19の確認

一項目ずつ確認し、次の項目へ進む前に`再読込`を押してください。詳しい合格条件は[05のブラウザー確認操作説明書](../05_Memory_Synapse_DB_サンプル検証キット/ブラウザー確認操作説明書.md)のB-01〜B-19と同じです。

| 済 | 確認する内容 |
|---|---|
| [ ] | B-01〜B-03、B-05：種類の異なる融合、Tag同士の融合、四枚融合 |
| [ ] | B-04、B-06：代表確認を終えるまで確定できず、代表競合時は人が選択することを確認する |
| [ ] | B-07〜B-08：読み取り専用集約、種類別手書き、空項目の元情報への戻り |
| [ ] | B-09〜B-11：構成カード・関係管理カードの分離、一枚になった場合の融合解除 |
| [ ] | B-12〜B-14：元に戻す、キャンセル、重複所属の拒否 |
| [ ] | B-15〜B-17：知識単位数、検索・絞り込み、所属状態の区別 |

## Vaultが変更されていないことの確認

### 分かりやすい確認

1. 06で融合、分離、手書きを試す。
2. `再読込`を押す。
3. 画面内の変更が消え、元の状態へ戻ることを確認する。
4. Obsidianで対象Markdownを開き、入力した手書き内容などが書き込まれていないことを確認する。
5. Obsidianを再起動しても元の状態であることを確認する。

### 厳密な確認を依頼する場合

ファイルが一つも変わっていないことをハッシュ値で検査できます。ターミナル操作に慣れていなければ、自分で行う必要はありません。Codexへ「06確認用Vaultが変更されていないか厳密に確認して」と依頼してください。

## 途中で止める条件

次のどれかが起きたら、有効化を解除し、それ以上操作せずに報告してください。

- 日常利用しているVaultを開いていた。
- `Memory Synapse DB`が有効化できない、または画面が開かない。
- 説明書にあるボタンが見つからない。
- Markdownが作成、変更、削除されたように見える。
- `再読込`やObsidian再起動後も、画面内で行った融合・手書きが残る。
- 外部サイトへの接続やログインを求められる。
- エラー通知が出る、カード件数が明らかに不足する、対象ルートを読み込めない。

報告時は、起きた画面、直前に押したボタン、スクリーンショットを伝えれば十分です。

## 無効化と削除

1. Obsidianの`設定` → `コミュニティプラグイン`で`Memory Synapse DB`を無効にする。
2. Obsidianを終了する。
3. **確認用Vaultの中だけ**にある次のフォルダーを削除する。

```text
<確認用Vault>/.obsidian/plugins/memory-synapse-db/
```

4. 不要なら、複製した確認用Vault全体を削除する。

日常利用Vault、元のサンプルVault、06に保管している配布元三ファイルは削除しません。

## 06の限界と次の段階

- 操作結果は画面内だけで、Markdownへ保存されない。
- ブラウザー確認用の90ケース画面やObsidian風の外枠は含まれない。
- 実データでの運用確認には使わない。
- 正式な保存機能を持つ08は別工程であり、06の確認完了だけでは作成・導入されない。

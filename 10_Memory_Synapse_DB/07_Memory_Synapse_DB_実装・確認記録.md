1. オーナーが決めた内容

5. 検証結果

コードを戻す場合は、対象コミットの内容を確認してから、現在の変更を失わない方法で取り消す。ブラウザー画面の「元に戻す」は検証用データの直前操作を戻す機能であり、ソースコードのロールバックとは区別する。

### 3.4 リンク一覧

- `Memory Synapse DB (リンク一覧)`の右側へ次を配置した。
  - 検索欄
  - Tag、Mention、Location
  - 単独、大きなカード、融合済み
  - 手書きあり
  - 絞り込み解除
  - `全○件中○件を表示`
- 通常の一覧では、融合済みの構成員を大きなカードへまとめ、一つの知識単位として数える。
- `融合済み`で絞り込んだ場合は、構成員自身を確認できる。
- 検索、種類、手書きの絞り込みは、大きなカードだけでなく融合グループ全体の情報を対象にする。
- 一覧カードにはドラッグ可能であることを示す`⠿`と説明を表示した。

### 3.5 融合先の選択

- `カードIDを入力してください`方式を廃止した。
- `融合へ追加`から次の順で進む。
  1. 選択中カード
  2. 検索・絞り込み
  3. 融合先候補のカード一覧
  4. 候補を選択
  5. 既存の融合確認画面
- 候補では名前、別名、種類、状態、関連投稿数を確認できる。
- カードを別カードへドラッグ＆ドロップしても、同じ融合確認画面へ進む。
- ドラッグした側、受け入れた側、システムの推奨だけでは大きなカードを確定しない。
- オーナーが候補を選ぶまで`融合する`を有効にしない。

### 3.6 融合、分離、解体と件数

- 二つの単独カードを融合すると、個別カードは残したまま、リンク一覧の知識単位を一件減らす。
- 融合済みの構成員を分離すると、リンク一覧の知識単位を一件増やす。
- Mention30件の状態で`@sazae_fuguta`と`@masuo_fuguta`を融合すると29件になり、分離すると30件へ戻ることを自動テストで確認した。
- 通常構成員の分離、大きなカード自身の分離、融合全体の解体を区別した。
- 大きなカードを分離する場合は、残る大きなカードを人間が選ぶ。
- 融合後も、各個別カードの固有情報、関連投稿、手書き情報を保持する。

### 3.7 大きなカードと受け皿

- 大きなカードは既存の個別カードから人間が選び、融合専用カードを自動生成しない。
- 受け皿には大きなカード自身を含む全構成員を平らに表示し、入れ子にしない。
- 通常表示では、大きなカード自身を受け皿内で`上に表示中`の短縮表示にする。
- 他の構成員は、元情報、手書き情報、関連投稿リンクを表示する。
- 手書き表示中は、手書き情報を上部へ表示し、元の個別カード情報を受け皿内で通常表示する。
- 単独カードに手書き情報がある場合も、手書き情報の下に移行時点の元情報を表示する。
- 投稿ログの右側に出る関連カードは、融合済み構成員を大きなカードへまとめて重複表示しない。

### 3.8 操作前後の共通確認

次の操作の確認画面を共通形式へ揃えた。

- 融合
- 通常構成員の分離
- 大きなカードの分離
- 融合全体の解体
- 大きなカードの変更
- 手書き情報の保存

共通して次を表示する。

- 現在の大きなカードと構成員数
- 操作後の大きなカードと構成員数
- 変更するファイル
- 変更しない情報
- 元に戻せるか

手書き保存では、現在の手書き情報と操作後の手書き情報も並べて表示する。

### 3.9 選択中カードの現在地

- 選択カードの詳細上部に、現在見ている関係を表示した。
- 融合グループ所属時は、次を表示する。
  - 融合グループ名
  - 大きなカード
  - 選択カードの役割が大きなカードか構成員か
- 単独時は`単独カード・どの融合グループにも所属していません`と表示する。
- 独自エクスプローラーではなく、選択中カードの関係を思い出すための表示とする。

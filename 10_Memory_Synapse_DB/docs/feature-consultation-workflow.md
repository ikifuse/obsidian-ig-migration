# Memory Synapse DB 機能・画面相談ワークフロー

## 目的と適用範囲

- オーナーが画面、ボタン、操作、情報の見え方または機能について質問したときに、質問への直接回答と、関係する一般的な既存例の補足を両立する。
- 対象はアイデア相談であり、企画、設計、仕様または実装の変更許可にはしない。
- 見た目の装飾案を増やすことではなく、目的を達成する操作と情報の見え方を考える。

## 相談の手順

1. オーナーの質問へ直接答え、実現したいことを短く確認する。
2. 一般的なDB、Wiki、検索、ファイル管理等の既存例から、今回の目的に関係する案だけを選ぶ。
3. 原則として一度に1〜3案を示し、推奨案がある場合は理由と注意点を添える。
4. オーナーの希望、AIの提案、採用済み事項を明示的に区別する。
5. 提案の採否が決まるまで、企画書、設計書、仕様書、コードまたは成果物を変更しない。
6. オーナーが明示的に「覚えておいて」「後で検討する」と指定した固有案だけを、`../../03_継続中の判断材料・引継ぎ/10_Memory_Synapse_DB_機能相談の判断材料.md`へ短く記録する。

## 記録しないもの

- 会話全文
- AIが一般知識として再提案できる機能一覧
- 今回の目的と関係しない案
- 採用されていない内容を確定事項に見せる記述

## 採用後の扱いと停止点

- 採用された内容は、影響する工程を確認し、企画、設計、仕様、実装の順序と各停止点に従って現役正本へ統合する。
- 判断材料だけを根拠に実装せず、相談結果と未確定事項を示して、次工程の明示承認を待つ。

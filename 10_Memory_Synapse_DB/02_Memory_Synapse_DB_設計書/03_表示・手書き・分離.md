# Memory Synapse DB 設計書 v1.0 — 表示・手書き・分離

## 第5章 表示と手書きによる成長

### 5.1 通常表示

融合時の大きなカード上部は、全個別カードから組み立てる読み取り専用の集約表示とする。Mention、Location、Tagの順に、存在するカテゴリの代表カードを最大一枚ずつ表示する。

カテゴリごとの表示は、一枚の代表カードの元情報と手書き情報だけから組み立て、異なる個別カードの値を出典不明の一項目へ混ぜない。各カテゴリに代表カード名と情報の出所を示し、同カテゴリの他の個別カードの件数と受け皿内の各カードへ到達できるようにする。

大きなカード上部へ集約結果を複製保存しない。受け皿には、関係を管理するカードを含む全個別カードを通常の単位で表示し、それぞれの元情報、手書き情報および関連投稿を確認できる状態を保つ。

### 5.2 手書き情報の編集と表示

手書きは、受け皿内の編集対象となる個別カードから開始する。関係を管理するカードも、受け皿内では一枚の個別カードとして同じ方法で編集できる。大きなカードの集約表示には手書きの編集入口を置かず、別の融合カードや手書き専用カードを自動生成しない。

入力した手書き情報は、選択した個別カード自身へ保持する。編集対象と異なる個別カード、融合関係または集約表示へコピー、移動または分配しない。

集約表示では、代表カードの各表示項目について、対応する手書き値があれば手書き値を優先し、なければ同じ代表カードの移行時点情報を表示する。グループ全体を通常表示または手書き表示のどちらか一方へ切り替えず、値の有無を項目単位で判定する。具体的な対応項目、空値の扱いおよび入力欄は仕様書で定める。

### 5.3 手書き情報の保護

手書き情報は、人間が育てた知識として、移行時点の情報と区別して保持する。関係を管理するカードの変更、分離、融合全体の解体によって表示上の参照関係が変わる場合も、人間の確認なしに削除、分配、上書きしない。

集約表示の再計算は個別カードの内容を変更しない。具体的な保持場所、編集単位、空欄、元情報との項目対応および代表関係の確認方法は仕様書で定める。

## 第6章 分離と組み直し

### 6.1 個別カードの分離

融合に参加したどの個別カードも、その一枚だけを分離できる。分離したカードは独立した個別カードとして戻り、元情報と関連投稿を保持する。

分離したカードの手書き情報も同じ個別カードに維持する。分離対象がカテゴリ別代表でなければ、残る代表関係を維持して集約表示を再計算する。

分離対象がカテゴリ別代表の場合、同カテゴリが残らなければそのカテゴリを集約表示から除く。同カテゴリが一枚だけ残る場合はそのカードを代表とし、複数残る場合は人間が次の代表を選ぶまで分離後の代表を確定しない。

### 6.2 関係を管理するカード自身の分離

現在の融合関係を管理している個別カードも分離対象にできる。誤って関係管理の主体にした場合だけに限定せず、人間が関係を見直す通常操作として扱う。

関係を管理しているカード自身を分離する場合は、残る構成員から次に関係を管理するカードを人間が選ぶ。システムは融合時と同じ基本順序で候補を提示できるが、自動確定しない。

関係を管理するカードが変わっても、残る構成員と確定済みのカテゴリ別代表は維持する。新しい関係管理カードが代表になることを自動的に強制しない。

### 6.3 構成員が一枚になる場合

分離後に構成員が一枚だけ残る場合、融合状態を終了し、そのカードを通常の個別カードとして扱う。融合管理だけを目的とする空の受け皿を残さない。

### 6.4 全体の解体と取消

一枚だけを外す分離、現在の関係管理カードを外す分離、融合全体の解体、直前操作の取消を区別する。

融合、分離、関係を管理するカードの変更およびカテゴリ別代表の変更は、複数の関係と集約表示へ影響し得る一操作として扱う。途中で一部だけが変更された状態を成功とせず、個別カードの元情報と手書き情報を維持したまま操作前へ戻すか、安全に再開できる単位を設ける。

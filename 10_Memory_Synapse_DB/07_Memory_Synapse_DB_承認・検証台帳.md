# Memory Synapse DB 承認・検証台帳

## この台帳の役割

05で試した変更が、設計・仕様、04、06へどこまで進んだかと、正本へ自然統合した後の変更経緯を、人間とAIがサイクルIDから追跡するための台帳です。

- オーナーが手動で更新する必要はありません。
- 一つの変更案件につき一つのサイクルIDを使い、索引の一行と同じIDの詳細節を更新します。
- 会話、試行、ボタン、承認発言ごとに別サイクルを増やしません。
- 変更前の問題、05で確かめた候補、採用・不採用と理由、正本への自然統合先、承認、検証結果、未確認事項、Git基準点は対象サイクル節へ詳しく残します。
- 設計・仕様の現在要件、コード差分全文、テスト出力全文、会話全文は複製しません。
- 正式実装の根拠は、承認済みの設計・仕様正本です。
- コードを戻す基準点はGitコミットです。この台帳だけでコードを復元しません。

## 読み方

- 通常作業では、先頭プロパティ、`現在地`、`変更サイクル索引`の対象行、今回の`サイクル詳細`だけを読みます。
- 設計書・仕様書にある`(YYYY-MM-DD / 07_台帳: サイクルID)`から経緯を調べる場合は、そのサイクル詳細だけを読みます。
- 過去全体の監査を依頼された場合だけ、この台帳を全文で読みます。
- 04の実装時は、承認済みの現役仕様を読みます。この台帳を仕様の代わりに読みません。

## 更新するタイミング

AIは次の場合に、先頭プロパティ、現在地、対象の索引行および同じサイクルIDの詳細節を更新します。

1. 新しい変更サイクルを開始したとき
2. 05完成候補と仕様差分を提示したとき
3. 設計承認が別に必要になったとき
4. 仕様が承認され、04実装へ進むとき
5. 04の自動検査が合格または不合格になったとき
6. 06を生成して実物確認を待つとき
7. 06が承認され、変更サイクルを完了したとき
8. 範囲外変更、未確認事項または不合格により停止したとき

05探索中の操作を一手ずつ列挙しません。意味のある候補、採用・不採用の判断、維持条件の変更、検査結果および停止理由は対象サイクル節へ要約し、細かな差分と復元点は許可された専用ブランチの`WIP（未承認）`コミットへ残します。

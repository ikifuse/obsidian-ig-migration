# Memory Synapse DB 仕様書 v1.0 — 融合・分離・取消・復旧

本分冊の状態変化、候補選択、確認画面および判定規則は、ブラウザー確認版、読み取り専用仮プラグイン、正式プラグインで共通とする。

第7.6節、第8章、第9章および第10.3節から第10.5節に記載するMarkdown更新と操作履歴の永続化は、書き込み可能な正式プラグインだけに適用する。ブラウザー確認版と読み取り専用仮プラグインでは、同じ更新案と操作結果をメモリ上の確認状態へだけ反映し、Vault内ファイルを変更しない。

## 第7章 融合操作

### 7.1 操作開始

ブラウザー確認画面とObsidianプラグインの両方で、次の入口を用意する。

- カードを別カードへドラッグ＆ドロップする
- カード内の`融合へ追加`から対象カードを選ぶ

ドラッグした側と受け入れる側のどちらが関係管理カードまたはカテゴリ別代表になるかを、操作だけで確定しない。

`融合へ追加`ではカードIDの手入力を求めず、次の順で進める。

1. 選択中カードを表示する。
2. 名前、別名、種類、状態、関連投稿による検索・絞り込みを表示する。
3. 融合先候補のカード一覧を表示する。
4. 人間が候補を一枚選択する。
5. 第7.5節の融合確認へ進む。

候補一覧には、少なくともカード名、別名、種類、単独・関係管理カード・融合済みの状態、関連投稿数を表示する。

### 7.2 構成員の展開

融合対象が単独カードなら、その一枚を候補集合へ加える。関係管理カードまたはその構成員なら、所属する融合単位の全カードを候補集合へ加える。

候補集合は重複を除去して平らな一つの配列にする。融合前の受け皿を入れ子で残さない。

### 7.3 関係管理カードの推奨

種類ごとの優先順位は次のとおりとする。

1. Mention
2. Location
3. Tag

候補集合内で最も優先順位が高い種類を推奨対象とする。同じ最高順位のカードが複数ある場合は、受け入れる側のカードまたは受け入れる側グループの現在の関係管理カードを第一候補とする。

第一候補にできない場合は、同順位のカードを全て「推奨」として表示し、自動選択しない。推奨は初期候補であり、人間は全構成員から別のカードを選べる。

### 7.4 カテゴリ別代表の候補

候補集合に存在するMention、Location、Tagごとに、集約表示へ使う代表を一枚決める。

- 同じカテゴリが一枚だけなら、そのカードを自動選択し、確認画面へ表示する。
- 融合前の確定代表が同カテゴリに一枚だけ残る場合は、その代表を初期選択として維持する。
- 融合前の確定代表が同カテゴリに複数残る場合は、いずれも自動選択しない。
- 確定代表がなく、関係管理カード候補が同カテゴリなら、そのカードを初期候補にする。
- それ以外は、候補集合の既存順で先にある同カテゴリのカードを初期候補にする。

同カテゴリが複数ある場合は、初期候補の有無にかかわらず、人間が確認画面で代表を一枚確認または変更する。カテゴリ間の優先順位だけで同カテゴリ内の代表を決定しない。

### 7.5 確認ポップアップ

融合のたびに、`融合関係を確認`と表示する。ポップアップには次を表示する。

- 全候補カードの種類とカード名
- 現在と操作後の関係管理カード
- 関係管理カードの推奨候補と推奨理由
- Mention、Location、Tagごとの現在と操作後の代表
- 同カテゴリの全候補と初期候補の理由
- 融合後の全構成員
- 第10.2節の操作前後比較
- `融合する`と`キャンセル`

関係管理カードと、存在する全カテゴリの代表が一枚ずつ確定するまで`融合する`を有効にしない。関係管理カードとカテゴリ別代表は同じカードでも異なるカードでもよい。

### 7.6 書き込み

確認後、次の順で更新案を作る。

1. 選択した関係管理カードを候補集合の先頭とする。
2. 残りを、既存の表示順を維持して`members`へ入れる。
3. 確定したカテゴリ別代表を`representatives`へ入れる。
4. 選択した関係管理カードへ`schema_version: 2`の`## Memory Synapse`を追加または更新する。
5. 融合前に関係管理カードだった別カードから`## Memory Synapse`だけを除く。
6. 全カードの`## 手書き情報`とカテゴリ固有情報を維持する。

変更対象を全て検証してから書き込む。一件でも読込不能、リンク切れ、解析不能、多重所属、代表未確定または代表不整合がある場合は、どのファイルも変更しない。

## 第8章 関係管理カードとカテゴリ別代表の変更

### 8.1 関係管理カードの変更

融合単位の`関係管理カードを変更`を押すと、現在の全構成員を候補とする選択ポップアップを表示する。第7.3節の推奨を表示するが、自動確定しない。

確認後、新しい関係管理カードへ同じ`members`と`representatives`を持つ`## Memory Synapse`を移し、旧関係管理カードから同見出しだけを除く。`members`は新しい関係管理カード自身を除いて組み直す。全構成員、カテゴリ別代表および各カードの手書き情報は維持する。

関係管理カードの変更だけを理由に、新しい関係管理カードをカテゴリ別代表へ変更しない。

### 8.2 カテゴリ別代表の変更

集約表示の各カテゴリに`代表を変更`を表示する。同じ融合単位に属する同カテゴリのカードだけを候補にし、カード名、元情報、手書き情報、関連投稿数および現在の代表を表示する。

人間が一枚を選び、操作前後比較を確認した後、関係管理カードの`representatives`にある該当カテゴリのWikiリンクだけを更新する。関係管理カード、`members`、個別カードの元情報および手書き情報は変更しない。

## 第9章 分離操作

### 9.1 通常構成員の分離

受け皿内の各構成員に`このカードを分離`を表示する。関係管理カード以外を選んだ場合は、確認後、そのWikiリンクだけを`members`から除く。

分離対象がカテゴリ別代表でない場合は、現在の`representatives`を維持する。分離対象がカテゴリ別代表の場合は、次の規則を操作前に適用する。

- 同カテゴリが残らない場合は、`representatives`からそのカテゴリを除く。
- 同カテゴリが一枚だけ残る場合は、そのカードを代表にする。
- 同カテゴリが複数残る場合は、人間が次の代表を選ぶまで分離を実行できない。

分離したカードのファイル内容は変更しない。残る全構成員数が二枚以上なら、現在の関係管理カードを維持する。

### 9.2 関係管理カード自身の分離

受け皿内の関係管理カード自身にも`このカードを分離`を表示する。選択した場合は残る構成員を表示し、`残す関係管理カードはどれにしますか？`と確認する。

残る構成員が二枚以上の場合は、人間が次の関係管理カードを選択する。推奨規則は第7.3節と同じとする。

旧関係管理カードがカテゴリ別代表でもある場合は、第9.1節と同じ規則でそのカテゴリの次の代表を確定する。関係管理カードの変更だけを理由に、他カテゴリの代表を変更しない。

確認後、旧関係管理カードから`## Memory Synapse`だけを除き、新しい関係管理カードへ残る構成員と確定した`representatives`を保存する。旧関係管理カードのカテゴリ固有情報と手書き情報は維持する。

### 9.3 一枚だけ残る場合

分離後に一枚だけ残る場合は、その一枚を単独カードへ戻す。`## Memory Synapse`は残さず、新しい関係管理カードまたはカテゴリ別代表の選択も求めない。

### 9.4 融合全体の解体

融合単位の`融合をすべて解体`を押すと、全構成員と影響を表示する。確認後、関係管理カードから`## Memory Synapse`だけを除く。

全個別カードのカテゴリ固有情報、関連投稿、手書き情報は変更しない。

## 第10章 取消・失敗・復旧

### 10.1 操作単位

次をそれぞれ一回の操作として扱う。

- 融合
- 関係管理カードの変更
- カテゴリ別代表の変更
- 一枚の分離
- 融合全体の解体
- 個別カードの手書き情報の保存

### 10.2 操作前後の共通確認

融合、一枚の分離、関係管理カード自身の分離、融合全体の解体、関係管理カードの変更、カテゴリ別代表の変更、手書き情報の保存では、実行前に同じ順序と見出しで次を表示する。

1. `現在`
   - 現在の関係管理カード
   - 現在のカテゴリ別代表
   - 現在の全構成員数
   - 対象となる個別カード
2. `操作後`
   - 操作後の関係管理カード
   - 操作後のカテゴリ別代表
   - 操作後の全構成員数
   - 単独へ戻るカードを含む操作後の状態
3. `変更するファイル`
   - `## Memory Synapse`または`## 手書き情報`を追加、更新、除去する全Markdownファイル
4. `変更しない情報`
   - 個別カードのカテゴリ固有情報
   - 関連投稿
   - Frontmatter
   - 対象操作で変更しない手書き情報
5. `元に戻せるか`
   - 第10.5節の取消対象になるか

候補選択が必要な操作では、人間が候補を選ぶまで操作後と変更ファイルを未確定として表示し、実行ボタンを有効にしない。

手書き情報の保存では、上記に加えて現在の`memory_synapse_note`と操作後の`memory_synapse_note`を並べて表示する。集約表示の計算結果は変更ファイルとして表示しない。

### 10.3 操作前検証

書き込み前に次を確認する。

- 全対象ファイルが存在する
- 全対象ファイルを読める
- 管理対象YAMLを解析できる
- 対象リンクを一意に解決できる
- 多重所属と入れ子がない
- 各カテゴリの代表が融合単位内の同カテゴリ一枚と一致する
- 構成員に存在する全カテゴリの代表が確定している
- 読み取り後に対象ファイルが別操作で変更されていない

一項目でも失敗した場合は書き込まず、原因と対象ファイルを表示する。

### 10.4 書き込みとロールバック

書き込み前に、変更対象ファイルごとに次をローカル操作履歴へ保持する。

- Vault相対パス
- 操作前の管理対象見出し内容
- 操作後の管理対象見出し内容
- 操作日時
- 操作種類
- 操作前後の内容照合値

複数ファイルの書き込み途中で失敗した場合は、書き込み済みファイルの管理対象見出しを操作前へ戻す。復旧にも失敗した場合は成功表示を出さず、変更済み・未変更・復旧失敗のファイルを分けて表示する。

### 10.5 直前操作の取消

画面に`元に戻す`を用意する。取消対象は最後に成功したMemory Synapse DB操作とする。

現在の管理対象見出しが履歴の操作後内容と一致する場合だけ取消を実行する。操作後に人間または別処理が編集している場合は自動で上書きせず、差分を表示して中止する。

操作履歴は`<Vault>/.obsidian/plugins/memory-synapse-db/operation-history.json`へ保存し、成功した直近100操作を保持する。101件目を保存した後に最古の一件を除く。履歴は知識関係の正本にはせず、Git管理、外部送信、SystemLogsへの混入の対象にしない。

### 10.6 読み取り専用環境での操作

ブラウザー確認版と読み取り専用仮プラグインでは、第7章から第10章の操作を次の条件で実行する。

- 融合、追加、関係管理カード変更、カテゴリ別代表変更、分離、解体、個別カードの手書き情報および取消の結果は、現在の画面セッション内の状態だけへ反映する。
- 確認画面の`変更するファイル`は、正式プラグインで永続化した場合に変更対象となる予定ファイルとして表示し、実際には変更しない。
- `元に戻す`は、画面セッション内で最後に成功した非永続操作を取り消す。
- `初期状態へ戻す`または再読込では、ブラウザー確認版は公開用検証データの初期状態、読み取り専用仮プラグインはVaultから再読込した状態へ戻す。
- 読み取り専用仮プラグインを閉じるか無効化した場合、非永続操作の状態と取消履歴を残さない。
- 対象ルート等のプラグイン設定を除き、Vault内のMarkdown、メディア、フォルダー、ファイル名および操作履歴ファイルを作成、変更、改名、移動または削除しない。

読み取り専用仮プラグインの画面には、操作が保存されないことと、再読込でVaultの状態へ戻ることを常時確認できる説明を表示する。書き込み処理へ到達できる非表示ボタン、コマンド、設定または代替経路を残さない。

# Memory Synapse DB 仕様書 v1.0 — ブラウザー確認・Obsidian実装・実物検証

## 第11章 ブラウザー確認画面

### 11.1 データ

ブラウザー確認では、実データを直接読み書きせず、次を含む検証用カードを使用する。

- Mention、Location、Tag各30枚
- Post、Reel、Story各30件の検証用投稿ログ
- 全カードと出現投稿が一致する、ハッシュタグ、メンション、場所の検証用SystemLogs
- 手書き情報があるカードとないカード
- 二つの融合済みグループ
- 問題がある場合だけ表示する検査欄を確認するための異常サンプル

ページ再読込で初期状態へ戻せるようにする。確認中の操作はブラウザー内の検証状態だけへ反映する。

### 11.2 画面構成

画面は次の三領域で構成する。

1. カード一覧
2. 選択中の大きなカードと受け皿
3. 確認ポップアップまたは手書き入力欄

カード一覧では種類、カード名、単独・融合済みの状態を確認できるようにする。種類は文字だけでなく、Mention、Location、Tagを区別できる表示を付ける。

ブラウザー確認画面の左側エクスプローラー、タブ、左右サイドバーの外枠は、検証用ログとカードを選び、Obsidianでの見え方を確認するための仮表示とする。正式プラグインの独自エクスプローラーまたは独自タブとして実装しない。

リンク一覧、検索・絞り込み、融合操作、選択中カードの現在地、受け皿、確認画面、問題検査表示は、ブラウザー確認で確定した操作として正式プラグインへ実装する。

### 11.3 必須操作

- ドラッグ＆ドロップによる融合開始
- `融合へ追加`
- 大きなカードの選択
- `大きなカードを変更`
- `手書き`
- `通常表示へ戻す`
- `このカードを分離`
- `融合をすべて解体`
- `元に戻す`
- `初期状態へ戻す`

### 11.4 確認ケース

| 番号 | 操作 | 合格条件 |
|---|---|---|
| B-01 | MentionとLocationを融合 | Mentionが推奨され、別カードも選択できる |
| B-02 | LocationとTagを融合 | Locationが推奨される |
| B-03 | Tag同士を融合 | 受け入れる側が推奨され、変更できる |
| B-04 | Mention同士を融合 | 受け入れる側が推奨され、変更できる |
| B-05 | 四枚を融合 | 全四枚が一つの受け皿に表示される |
| B-06 | 大きなカード同士を融合 | 入れ子にならず全構成員が一列の受け皿になる |
| B-07 | 通常表示 | 大きなカードは上部に通常表示、受け皿では短縮表示される |
| B-08 | 手書き表示 | 手書き情報が上部、元の大きなカード情報が受け皿で通常表示される |
| B-09 | 通常構成員を分離 | 選んだ一枚だけが単独カードへ戻る |
| B-10 | 大きなカードを分離 | 次の大きなカードを選べ、元情報を失わない |
| B-11 | 一枚だけ残す | 融合状態と空の受け皿が消える |
| B-12 | 元に戻す | 直前操作前の状態へ戻る |
| B-13 | キャンセル | 状態が一切変わらない |
| B-14 | 多重所属を試す | 実行されず、理由と対象が表示される |
| B-15 | 一覧件数 | 融合で知識単位が減り、分離または解体で増えるが、個別カード数は変わらない |
| B-16 | 検索・絞り込み | 種類、状態、手書き、名前、別名、関連投稿で対象を絞り、全件数と表示件数を区別できる |
| B-17 | 現在地 | 単独、大きなカード、構成員のいずれを見ているか判別できる |
| B-18 | 操作前後比較 | 融合、分離、解体、大きなカード変更、手書き保存で同じ比較項目を確認できる |
| B-19 | 問題検査表示 | 正常時は表示せず、異常時だけ種類別件数と対象ファイルを表示し、自動修復しない |

各ケースは、結果だけでなく、オーナーが操作の意味と影響を迷わず理解できるかを確認する。

## 第12章 Obsidianプラグイン

### 12.1 実装条件

- TypeScriptで実装する。
- macOS / iMac M4のデスクトップ版Obsidianを最終対象とする。
- ObsidianのVault読込、Markdown変更、リンク生成機能を使用する。
- Pythonサーバーを、融合・分離・手書きの必須条件にしない。
- 外部ネットワークへ自動接続しない。
- プラグイン内部だけに融合関係の正本を保存しない。
- 正式プラグインの生成先は`08_Memory_Synapse_DB_正式プラグイン/memory-synapse-db/`とする。
- `06_Memory_Synapse_DB_仮プラグイン/`は読み取り専用の技術検証成果物のまま維持し、正式プラグインへ書き換えない。
- `05_Memory_Synapse_DB_ブラウザー確認版/`は今後のUIテスト・モック環境として恒久的に維持する。正式プラグインが第13章の検証に合格した後に、別工程で`99_完了済み参考資料`へ退役させるのは`06_Memory_Synapse_DB_仮プラグイン/`のみとする。正式プラグインの実行は05または06へ依存しない。

### 12.2 読み込み

起動時に対象ルート内のMarkdownを読み、次の索引をメモリ上に作る。

- カードパスからカード種類
- 大きなカードから全構成員
- 構成員から所属する大きなカード
- Wikiリンクから解決先

対象ファイルの作成、変更、改名、移動、削除を検知した場合は、影響する索引を更新する。リンク切れや不正状態を検出した場合は、自動修復せず表示する。

通常時は問題検査欄を表示しない。問題を検出した場合だけ、少なくとも次を種類別件数で表示する。

- Wikiリンク切れ
- 複数所属または入れ子の疑い
- `## Memory Synapse`または`## 手書き情報`の管理形式不正
- YAML解析失敗
- 未対応`schema_version`

問題表示には`対象ファイルを開く`を用意し、Obsidian標準のファイル表示で対象Markdownを開く。問題を検出した状態では、第10.3節に従って対象操作を書き込まない。

### 12.3 Markdown更新

Markdown更新では、管理対象見出し以外を変更しない。Frontmatter、カテゴリ固有YAML、関連投稿、未知の本文、改行を維持する。

文字コードはUTF-8（BOMなし）とする。既存ファイルの改行コードは維持する。

### 12.4 画面統合

- リンク一覧はObsidianワークスペース内のMemory Synapse DB専用ビューとして開く。
- 選択中カードの詳細、現在地、操作ボタン、大きなカードと受け皿は右サイドバーのMemory Synapse DBビューへ表示する。
- 融合先候補、大きなカード候補、操作前後比較、手書き入力はObsidianのモーダルまたは同等の一時画面へ表示する。
- ファイルを開く操作、通常のタブ、左側エクスプローラーはObsidian標準機能を使用する。
- 正式プラグインは左側へ独自エクスプローラーを追加せず、ブラウザー確認用のObsidian風外枠を再実装しない。

### 12.5 外部AI

v1.0では、外部AIへデータを送る機能を実装しない。将来追加する場合は、送信対象、目的、確認画面、送信しない選択肢を別仕様として承認する。

## 第13章 Obsidian実物検証

### 13.1 検証用データ

最初は実Vaultの複製または専用の検証Vaultを使用する。日常利用Vaultへ直接導入しない。

### 13.2 合格条件

- 第11.4節の全操作をObsidian上でも再現できる。
- MarkdownをObsidian標準画面で開き、融合関係と手書き情報を読める。
- Wikiリンクから各個別カードと関連投稿へ移動できる。
- 個別カードのフォルダーとファイルが融合前後で変わらない。
- 新しい融合専用カードが生成されない。
- カテゴリ固有情報、関連投稿、Frontmatterが融合前後で一致する。
- 手書き補正によって投稿Frontmatterが変更されない。
- 大きなカード同士を融合しても入れ子にならない。
- 分離、解体、取消後も全カードと手書き情報が残る。
- リンク一覧の知識単位件数が融合で減り、分離または解体で増える。
- 選択中カードの現在地が、単独、大きなカード、構成員の状態と一致する。
- 操作前後比較の変更ファイルと、実際に変更された管理対象見出しが一致する。
- 不正状態では問題種類、件数、対象ファイルを表示し、Markdownを自動修復しない。
- Obsidian標準エクスプローラーと標準タブを使用し、独自エクスプローラーを追加しない。
- プラグイン停止中でもMarkdownから主要な関係を確認できる。
- 外部通信が発生しない。

### 13.3 不合格時

一項目でも成立しない場合は、プラグイン完成としない。仕様と実装のどちらが原因かを自動的に決めず、確認済み事実、影響、変更候補を分けて報告する。

## 第14章 対象外

- AIによる意味上の同一性の自動確定
- 人間の確認を経ない自動融合・自動分離
- 未確定候補を長期間保存する常設作業台
- Instagram以外の情報源の取込み
- IGX
- 複数の大きなカードへの同時所属
- 受け皿の入れ子
- 投稿Frontmatterへの位置情報同期
- 実データを使ったブラウザー確認
- ブラウザー確認用の左側エクスプローラー、タブ、左右サイドバー外枠の正式プラグインへの移植
- 読み取り専用仮プラグインを正式プラグインへ上書きすること

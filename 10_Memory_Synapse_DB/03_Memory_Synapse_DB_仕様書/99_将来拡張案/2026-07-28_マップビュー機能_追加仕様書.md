## 第1章 座標の読み取りと優先順位

### 1.1 データソースの定義

マップピンの座標は、以下の2つのソースから取得する。

**ソース1：移行時点の座標（元データ）**

Locationカードのカテゴリ固有YAMLに含まれる `geo` フィールド。TypeScript上は `LocationSource.geo`（`カード.ts` 26-30行目）として定義されている。

```yaml
# Markdownでの記述（カテゴリ固有情報内）
geo:
  lat: 34.62
  lng: 135.43
  alt: null
```

TypeScript型定義：
```typescript
// カード.ts 26-30行目
geo: {
  lat: number | null;
  lng: number | null;
  alt: number | null;
}
```

**ソース2：手書き補正座標（人間による補正）**

`## 手書き情報` セクション内の `memory_synapse_note.geo` フィールド。仕様書 `03_表示・手書き情報.md` 93-96行目で定義されている。TypeScript上は `保存用手書き情報.geo`（`手書き情報.ts` 28-32行目）として定義されている。

```yaml
# Markdownでの記述（## 手書き情報 セクション内）
memory_synapse_note:
  geo:
    lat: 34.6873
    lng: 135.5262
    alt: null
```

TypeScript型定義：
```typescript
// 手書き情報.ts 28-32行目（保存用）
geo: {
  lat: number | null;
  lng: number | null;
  alt: number | null;
}

// 手書き情報.ts 9行目（画面表示用）
geo: { lat: string; lng: string; alt: string }
```

画面表示用（`手書き情報`型）では座標が文字列で保持されており、保存時に `parseNum` 関数（`手書き情報.ts` 66-69行目）で `number | null` へ変換される。マップピン生成時は保存用の `number | null` 型で扱う。

### 1.2 座標ペアの有効性判定

座標は緯度（lat）と経度（lng）のペアとして判定する。altは地図描画には使用しないが、保持する。

**判定規則：**

1. `Number.isFinite(lat)` かつ `-90 <= lat <= 90` であること
2. `Number.isFinite(lng)` かつ `-180 <= lng <= 180` であること
3. 上記の両方を満たす場合にのみ、そのペアを「有効」とする
4. `lat: 0, lng: 0`（ギニア湾沖）は地理的に正常な座標であり、有効として扱う
5. 片方でも `null`、範囲外、`NaN`、`Infinity` であれば、ペア全体を「無効」とする

```typescript
function isValidGeoPair(lat: unknown, lng: unknown): boolean {
  return (
    typeof lat === "number" && Number.isFinite(lat) && lat >= -90 && lat <= 90 &&
    typeof lng === "number" && Number.isFinite(lng) && lng >= -180 && lng <= 180
  );
}
```

### 1.3 座標の優先順位とフォールバック

一つのLocationカード（または融合グループの代表カード）に対して、以下の順序で座標を決定する。

1. **手書き補正座標を最優先で確認する**
   - `handwritten.geo.lat` と `handwritten.geo.lng` を `parseNum` で数値化し、1.2節の判定を行う
   - 画面用データが文字列型（`手書き情報.geo`）の場合は、数値変換後に判定する
   - 両方有効 → この座標を採用
   - 片方でも無効 → 手書きペア全体を破棄し、次へ進む

2. **移行時点座標を確認する**
   - `source.geo.lat` と `source.geo.lng` に対して1.2節の判定を行う
   - 両方有効 → この座標を採用
   - 片方でも無効 → 次へ進む

3. **座標なし**
   - マップピン生成対象から除外する
   - 除外されたカード数は画面上に「座標なし: ○件」として表示する

## 第2章 融合グループとマップピンの集約

### 2.1 基本規則

`03_表示・手書き情報.md` 5.4節の規定に従い、マップ上でも融合グループ全体を一知識単位として扱う。

- **単独カード**: 1枚のLocationカードにつき1ピン
- **融合グループ**: グループ全体で1ピン。代表座標は大きなカードの座標を使用する

### 2.2 代表座標の決定

融合グループのピン位置は、大きなカード（`bigCardId`）の座標を使用する。

1. 大きなカードがLocationカードであり、有効な座標を持つ場合 → その座標を使用
2. 大きなカードがLocationカードでない場合（Mention等）、または座標が無効な場合 → グループ内のLocationカード構成員のうち、最初に有効な座標が見つかったものを使用
3. グループ内にLocationカードが存在しない、または全て座標無効 → ピンを生成しない

### 2.3 吹き出し（ポップアップ）の内容

ピンをクリックした際に表示する情報：

- カード名（手書きの `display_name` があればそちらを優先）
- カード種類（Location / Mention / Tag）
- 融合グループの場合は構成員数
- 「詳細を開く」ボタン → 選択制御APIを通じてカード詳細を表示

## 第3章 関連投稿とWikiリンクの重複排除

### 3.1 現行の関連投稿構造

`main.js` 内のデータを確認すると、各カードの `relatedPosts` はWikiリンク文字列の配列として保持されている。

```javascript
// main.js内のデータ例（location-大阪城）
relatedPosts: ["[[2026-01-30-15-00-00_IG_0001]]"]
```

### 3.2 重複排除の方針

ブラウザー確認版（`05`）ではWikiリンク文字列の完全一致で管理されている。Obsidianプラグイン版では、`app.metadataCache.getFirstLinkpathDest` を用いてリンク先のVault相対パスに解決し、`Set<string>` で重複排除する。

マップの吹き出しに関連投稿数を表示する場合は、この重複排除後の件数を使用する。

## 第4章 XSS防御

### 4.1 現行コードの状況

`共有UI.ts` および `ブラウザー画面.ts` はHTML文字列テンプレートで画面を構築しているが、エスケープ関数 `r()` を通してからHTMLへ埋め込んでいる。

### 4.2 マップビューでの規則

Leafletの `L.popup()` に渡すDOM要素は、HTML文字列ではなく `HTMLElement` を使用する。テキスト内容は `element.textContent` で設定し、`innerHTML` は使用しない。

```typescript
// マップの吹き出し生成例
function createPopupContent(card: LocationCard): HTMLElement {
  const container = document.createElement("div");

  const title = document.createElement("strong");
  title.textContent = card.handwritten?.displayName || card.name;
  container.appendChild(title);

  const kind = document.createElement("span");
  kind.textContent = ` (${card.kind})`;
  container.appendChild(kind);

  const btn = document.createElement("button");
  btn.textContent = "詳細を開く";
  btn.addEventListener("click", () => selectCard(card.id));
  container.appendChild(btn);

  return container;
}
```

## 第5章 外部通信とプライバシー

### 5.1 デフォルト状態

プラグイン設定の初期値：`mapOnlineEnabled: false`

この状態では地図タイルの取得を行わない。地図領域には「通信が無効です。設定からオンライン地図を有効にできます。」と表示する。ローカル画像による代替表示（`L.imageOverlay`）を提供するかどうかは実装時に判断する。

### 5.2 オプトイン有効化

設定画面に以下の注意事項を表示し、利用者が明示的に有効化した場合のみ `mapOnlineEnabled: true` とする。

表示する注意事項：
- 地図タイルの取得時にIPアドレスがタイルサーバーへ送信されること
- タイル番号から表示地域が推定される可能性があること
- OpenStreetMapの利用規約に準拠すること

### 5.3 ライブラリの内蔵

Leaflet.jsおよびLeaflet.cssは `npm install leaflet` でインストールし、esbuildのバンドルでプラグインの `main.js` へ内蔵する。unpkg、cdnjs、その他の外部CDNからのスクリプト・スタイルシート取得は行わない。

## 第6章 Leafletインスタンスのライフサイクル

### 6.1 生成と破棄

`ItemView.onOpen()` でLeafletのマップインスタンスを生成し、`ItemView.onClose()` で `map.remove()` を呼んで破棄する。タブの切り替え時にインスタンスが蓄積してメモリリークが発生しないようにする。

### 6.2 リサイズ対応

Obsidianのサイドバーやペインのリサイズイベントに対して `map.invalidateSize()` を呼び出し、地図の表示領域を正しく再計算する。

## 第7章 選択制御APIとの連携

### 7.1 現行の構造（課題）

`共有UI.ts` 46行目の `let selectedCardId` はモジュールスコープの変数であり、外部のモジュール（マップ画面等）から変更する手段がない。`mountUI` 関数（65-76行目）も、外部からの選択カード変更通知を受け取るインターフェースを持たない。

### 7.2 必要な変更

マップビュー実装時に、以下のいずれかの方法で選択制御を分離する。

**案A：コールバック方式**
`mountUI` に `onExternalSelect: (cardId: string) => void` コールバックを追加し、外部から選択カードを変更できるようにする。

**案B：イベント方式**
`CustomEvent` を使い、`document.dispatchEvent(new CustomEvent("msdb-select-card", { detail: { cardId } }))` で選択を通知する。`共有UI.ts` 側でこのイベントをリッスンする。

どちらの方式を採用するかは、マップ実装開始時に現行コードの状況を見て判断する。いずれの方式でも、v1.0のコード変更が必要となるため、オーナーの承認を得てから実施する。

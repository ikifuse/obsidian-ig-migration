# Memory Synapse DB 仕様書 v1.0 — 表示・手書き情報

## 第5章 読み取り専用集約表示と受け皿

### 5.1 カード上部

融合単位のカード上部には、`representatives`から組み立てた読み取り専用の集約表示を置く。カテゴリは、存在するものだけをMention、Location、Tagの順に最大一件ずつ表示する。

各カテゴリには、カテゴリ名、代表カード名、各表示項目、情報の出所、同カテゴリの構成員数および`他のカードを見る`を表示する。`他のカードを見る`は受け皿内の同カテゴリへ移動する。代表でないカードを集約表示の値へ混ぜない。

表示項目は代表カードの種類ごとに次のとおりとする。

| 種類 | 主表示 |
|---|---|
| Tag | 表示名、元表記、別名、自由メモ |
| Mention | 表示名、元の`@文字列`、別名、名前、電話番号、Web、自由メモ |
| Location | 表示名、元の場所名、別名、座標、住所、活動ID、元ファイル、人間の記憶 |

項目の実効値は、同じ代表カードの手書き値が空でなければ手書き値、空なら同じカードのカテゴリ固有情報とする。文字列は`null`または空文字、配列は空配列、座標・住所の子項目は子項目ごとの`null`を空と判定する。手書き値と元情報のどちらも空なら閲覧画面ではその項目を省略する。

対応する手書き項目と元情報は次のとおりとする。

| 種類 | 表示項目 | 手書き項目 | 空の場合に使う元情報 |
|---|---|---|---|
| Tag | 表示名 | `display_name` | `hashtag_note.hashtag` |
| Tag | 別名 | `aliases` | なし |
| Tag | 自由メモ | `note` | `hashtag_note.note` |
| Mention | 表示名 | `display_name` | `mention_note.mention` |
| Mention | 別名 | `aliases` | なし |
| Mention | 名前 | `name` | `mention_note.name` |
| Mention | 電話番号 | `phone` | `mention_note.phone` |
| Mention | Web | `web` | `mention_note.web` |
| Mention | 自由メモ | `note` | `mention_note.note` |
| Location | 表示名 | `display_name` | `location_note.location` |
| Location | 別名 | `aliases` | なし |
| Location | 緯度・経度・高度 | `geo.lat`、`geo.lng`、`geo.alt` | `geo.lat`、`geo.lng`、`geo.alt` |
| Location | 住所全文・住所内訳 | `address.full`、`address.components.*` | `address.full`、`address.components.*` |
| Location | 人間の記憶 | `note` | `note` |

`display_name`と`aliases`は手書き情報だけに存在する。`display_name`が空の場合、Tagは`hashtag_note.hashtag`、Mentionは`mention_note.mention`、Locationは`location_note.location`を表示名に使用する。`activity_id`と`source_files`はLocationの元情報だけを表示し、手書き値で置き換えない。

各実効値には`手書き`または`移行時点`を表示する。集約結果は画面表示のたびに計算し、Markdown、`memory_synapse`または別ファイルへ保存しない。

関連投稿は件数だけで終わらせず、元のWikiリンクを開けるようにする。投稿本文内の `#タグ` や `@メンション`、プロパティ、写真下の末尾Wikiリンク（`[[...]]`）の選択で対応するSynapseカードを右パネル（Memory Synapse）へ呼び出し・展開表示し、右パネルの関連投稿選択で中央領域の投稿ノートを即座に追従表示する相互逆引き連動を備える。 `(2026-08-01 / 07_台帳: MSDB-2026-08-01-01)`

`SystemLogs` ノート閲覧時は、`- [x]` チェックボックス記法および出現投稿へのインデントツリー構造をObsidian標準のログ表示スタイルとしてレンダリングし、ツリー内の各項目リンク選択で右パネルまたは対象投稿へ即座に移動できる。 `(2026-08-01 / 07_台帳: MSDB-2026-08-01-01)`

### 5.2 受け皿

受け皿は集約表示の下部に表示し、先頭に関係管理カード、その後に`members`の順で全構成員を並べる。

関係管理カードを含む全構成員は同じ個別カード形式で表示し、次を省略しない。

- 種類、カード名
- カテゴリ固有情報
- `## 手書き情報`がある場合の手書き情報
- 関連投稿リンク
- 関係管理カードかどうか
- カテゴリ別代表かどうか
- `手書き`
- `このカードを分離`

集約表示に使われていることを理由に、関係管理カードまたは代表カードを短縮しない。個別カードの値と集約表示の値を対応づけられるよう、同じ代表表示を付ける。

### 5.3 単独カード

`## Memory Synapse`がなく、他の関係管理カードにも所属しないカードは単独カードとして表示する。受け皿は表示しない。

単独カードでも`手書き`を表示し、同じファイルへ手書き情報を保存できる。ただし、構成員が一枚だけの`memory_synapse`は作らない。単独カードに手書き情報がある場合も、第5.1節と同じ項目単位の実効値を上部に表示し、その下で元のカテゴリ固有情報と手書き情報を別々に確認できるようにする。

### 5.4 リンク一覧

リンク一覧の通常表示では、単独カード一枚を一知識単位、融合グループ全体を一知識単位として数える。融合グループの構成員である個別Markdownファイルは削除せず、通常表示の一覧件数に重複して数えない。

一覧上部に次を表示する。

- カード名、別名、元情報、関連投稿を対象とする検索欄
- `Tag`、`Mention`、`Location`の種類絞り込み
- `単独`、`関係管理カード`、`融合済み`の状態絞り込み
- `手書きあり`
- `絞り込み解除`
- `全○件中○件を表示`

検索、種類、手書きの判定は、関係管理カードだけでなく、その融合グループに属する全個別カードを対象とする。`融合済み`を選んだ場合は、構成員自身を個別に確認できる一覧へ切り替える。

融合で二つ以上の知識単位を一つへまとめた場合は一覧件数を減らし、分離または解体で独立した知識単位へ戻した場合は一覧件数を増やす。これは画面上の知識単位の数であり、Vault内の個別Markdownファイル数を増減させる処理ではない。

### 5.5 選択中カードの現在地

選択中カードの詳細上部に、現在見ているカードと融合関係を表示する。

融合グループ所属時は、次の順で表示する。

```text
融合グループ「関係管理カードの実効表示名」 → 関係管理カード：カード名 → このカードの役割：関係管理カード・カテゴリ代表・構成員の該当項目
```

単独カードでは、次を表示する。

```text
単独カード・どの融合グループにも所属していません
```

この表示は選択中カードの関係を確認するためのものであり、独自のファイルエクスプローラー、保存用の融合グループIDまたは新しいMarkdownファイルを追加しない。

## 第6章 手書き情報

### 6.1 保存場所

手書き情報は、手書きを行った個別カード自身の`## 手書き情報`へ保存する。融合状態とは独立して保持し、関係管理カードまたはカテゴリ別代表の変更、分離、解体で自動削除しない。

### 6.2 YAML形式

````markdown
## 手書き情報

```yaml
memory_synapse_note:
  display_name: null
  aliases: []
  name: null
  phone: []
  web: []
  geo:
    lat: null
    lng: null
    alt: null
  address:
    full: null
    components:
      country: null
      prefecture: null
      city: null
      district: null
      street: null
      postal_code: null
  note: null
```
````

| 項目 | 型 | 初期値 | 用途 |
|---|---|---|---|
| `display_name` | 文字列または`null` | `null` | 個別カードに人間が付ける表示名 |
| `aliases` | 文字列配列 | `[]` | 人間が確認した別名 |
| `name` | 文字列または`null` | `null` | 人・店舗・団体等の名称 |
| `phone` | 文字列配列 | `[]` | 確認した電話番号 |
| `web` | 文字列配列 | `[]` | Web、メール、SNS等 |
| `geo.lat` | 数値または`null` | `null` | 人間が確認・補正した緯度 |
| `geo.lng` | 数値または`null` | `null` | 人間が確認・補正した経度 |
| `geo.alt` | 数値または`null` | `null` | 人間が確認・補正した高度 |
| `address.full` | 文字列または`null` | `null` | 人間が確認・補正した住所全文 |
| `address.components.*` | 文字列または`null` | `null` | 人間が確認・補正した住所内訳 |
| `note` | 文字列または`null` | `null` | 意味、記憶、判断等の自由メモ |

空文字は保存時に`null`へ変換する。複数値欄の空行は除去し、入力順を維持する。同じ値は一件にする。空値は元情報を消す指定として扱わない。

### 6.3 手書き操作

1. 単独カードまたは受け皿内の個別カードにある`手書き`を押す。
2. 選択したカードの種類に対応する入力欄だけを、現在の手書き値または初期値で表示する。
3. `保存内容を確認`では現在値と操作後の値、変更する一ファイル、変更しない情報、取消可否を表示する。
4. 確認後、選択した同じファイルの`## 手書き情報`だけを追加または更新する。
5. `キャンセル`では画面状態とMarkdownを変更しない。

入力欄は次のとおりとする。

| 種類 | 編集できる項目 |
|---|---|
| Tag | 表示名、別名、自由メモ |
| Mention | 表示名、別名、名前、電話、Web等、自由メモ |
| Location | 表示名、別名、緯度、経度、高度、住所全文、国、都道府県、市区町村、地区、番地等、郵便番号、自由メモ |

大きなカードの集約表示には`手書き`を置かない。関係管理カードを編集する場合も、受け皿内の同カードから開始する。

既存の`memory_synapse_note`に、そのカード種類の編集画面へ出さない非空項目がある場合は、`保存済みのその他項目`として読取専用で表示し、保存時に削除または空へ変更しない。

### 6.4 手書き情報を反映した表示

単独カード、受け皿内の個別カード、集約表示および右サイドバーの選択中カード詳細は、第5.1節の項目単位の実効値判定を共通で使う。カード全体を元情報表示または手書き表示のどちらかへ切り替える`display_mode`と`通常表示へ戻す`は使用しない。

手書き値がある項目は手書きを優先し、同じカードの元情報は削除または上書きしない。閲覧画面には実効値を先に表示し、`元情報を見る`から同じ個別カードの移行時点情報を確認できるようにする。

### 6.5 補正情報

位置情報や住所を人間が補正する場合は、Locationカード自身の`memory_synapse_note.geo`または`memory_synapse_note.address`へ保存する。

次は変更しない。

- Locationカードの移行時点の`geo`と`address`
- 関連投稿のFrontmatter
- Instagram原本
- `output_IGC`の上流成果物

画面では項目ごとに「移行時点」と「手書き・補正後」を区別して表示する。

# Memory Synapse DB 実行コード目次

## 1. このフォルダーの役割

ここには、承認済みのMemory Synapse DB仕様をObsidianプラグインへ実装する、人間が読めるTypeScript元コード、依存関係、テスト、manifest原本、スタイルおよびビルド設定を置く。

本フォルダーは実装正本である。`05_Memory_Synapse_DB_サンプル検証キット/`のサンプルデータ、検証ケース台帳、サンプルメディア、UIモックまたはObsidian風の仮外枠を、通常ビルドの入力または出力として管理しない。

人間が読むTypeScript本体は`TypeScript元コード/`へまとめ、役割が重ならない次の5つに分ける。番号は処理の流れを示すもので、別々のアプリケーションを意味しない。

| 番号 | フォルダー | 役割 |
|---|---|---|
| 01 | [01_データ構造](TypeScript元コード/01_データ構造/00_このフォルダーの役割.md) | カード、融合状態、手書き情報、操作結果の形を定める |
| 02 | [02_操作処理](TypeScript元コード/02_操作処理/00_このフォルダーの役割.md) | 融合、分離、変更、検証、取消の規則を実行する |
| 03 | [03_データ入出力](TypeScript元コード/03_データ入出力/00_このフォルダーの役割.md) | Obsidian VaultのMarkdown読込、索引および対象パス判定を受け持つ |
| 04 | [04_画面](TypeScript元コード/04_画面/00_このフォルダーの役割.md) | Obsidian内の一覧、詳細、確認画面および標準タブへの移動を受け持つ |
| 05 | [05_共通処理](TypeScript元コード/05_共通処理/00_このフォルダーの役割.md) | 設定、入力値整理、エラーおよび共通型を受け持つ |

## 2. 処理の流れ

```text
TypeScript元コード/
├── 01_データ構造
│       ↓
├── 02_操作処理 ← 03_データ入出力
│       ↓
├── 04_画面
│       ↑
└── 05_共通処理
```

画面は融合規則を独自判断せず、`02_操作処理`を呼び出す。Vaultの読込と将来の保存処理は操作処理へ直接埋め込まず、`03_データ入出力`で分離する。

## 3. 05・06・08との関係

| 対象 | 本フォルダーとの関係 |
|---|---|
| `../05_Memory_Synapse_DB_サンプル検証キット/` | 公開用サンプルデータとUIモックを保持する独立検証キット。04の通常ビルドでは生成・変更しない |
| `../06_Memory_Synapse_DB_仮プラグイン/memory-synapse-db/` | 04の通常ビルドから生成する、読み取り専用の公開技術検証版 |
| `../08_Memory_Synapse_DB_正式プラグイン/memory-synapse-db/` | 06の検証後、書き込み可能な正式実装が別に承認された場合だけ生成する正式版 |

06または08の生成物だけを直接修正しない。変更は本フォルダーのTypeScript、テスト、manifest原本、スタイルまたはビルド設定へ行い、対応する生成先へ再ビルドする。

通常ビルドは06だけを生成し、05または08へ書き込まない。08の生成は、オーナーが対象、書き込み範囲、復旧試験および停止点を別に承認するまで実行しない。

## 4. 現在の境界

> [!warning] 06は読み取り専用技術検証版
> 06はVaultのSynapseと関連投稿を読み、承認済みの画面、標準タブへの移動および非永続操作を確認する。Markdownの作成、変更、改名、移動、削除、融合状態、手書き情報または操作履歴の保存を行わない。再読込するとVaultから読み取った状態へ戻る。

- 06はサンプルVaultと利用者自身の変換成果物を同じVault入力として扱い、サンプル専用分岐を持たない。
- 写真、動画、本文、タグ、メンション、位置情報および末尾リンクは、投稿MarkdownとObsidian標準表示へ任せる。
- 05の検証番号、サンプル名称、サンプルメディア、仮のエクスプローラーまたは仮タブを06・08へ組み込まない。
- 06の合格を、08の実装許可またはMemory Synapse DB全体の完成へ読み替えない。

ビルド、コード監査および検証方法は[99_ビルド・検証方法.md](99_ビルド・検証方法.md)を参照する。

# 10 Memory Synapse DB地図企画書 v0.1

## 1. 位置付け

本孫プロジェクトは、Memory Synapse DBが親成果物を利用しながら、親完成とは独立して進む後続プロジェクトであることを理解する地図を作る。

企画、設計、仕様、コード、ブラウザー確認版、仮プラグイン、人間判断による融合・分離・復旧の関係を整理する。

## 2. 必要になった理由

Memory Synapse DBは親プロジェクトと同じリポジトリ内にあり、親成果物を利用するため、親工程の一部に見えやすい。

しかし、その完成を親プロジェクトの完成条件へ含めたり、後続の要求を完成済み上流工程へ戻したりしてはならない。独立性と接続点を同時に理解する専用地図が必要である。

## 3. この地図で答える問い

- Memory Synapse DBは何のために作るのか
- 親プロジェクトから何を受け取るのか
- なぜ親完成とは独立した後続なのか
- 企画、設計、仕様、コードはどう分かれるか
- ブラウザー確認版と仮プラグインは何のためにあるか
- 人間判断による融合、分離、復旧はどこで働くか
- 後続の要求を上流へ戻さない境界はどこか

## 4. 主な利用者

- 親プロジェクトとの境界を確認するオーナー
- Memory Synapse DBの構造を思い出す人
- 親完成条件と後続要求を混同しないために確認するAI

## 5. 表す範囲

- 独立後続としての目的
- 親成果物との接続
- 企画、設計、仕様、実行コード
- ブラウザー確認版と仮プラグイン
- 融合、分離、復旧における人間判断
- 親プロジェクトへ戻さない責任境界

## 6. 表さない範囲

- 実際の人物、投稿、記憶内容
- 実データやブラウザー画面
- 親プロジェクトの完成条件への組み込み
- 後続要求によるIGP・IGR・IGSの変更
- 未承認の将来機能

## 7. 表現方針

表現形式は未確定とする。プロジェクト構造を示す関係図、データと操作の流れを示すフロー、人間判断の分岐を示す決定木を比較する。単に中心から項目を並べるだけのマインドマップには固定しない。

## 8. 公開とデータ保護

公開承認済みの役割、構造、抽象化した操作だけを使用する。実際の記憶、人物、投稿、アカウント、画像、ログ、ローカルパスを絶対に使用しない。

## 9. 完成条件

1. 独立後続である理由を説明できる。
2. 親から受け取るものと親へ戻さないものを区別できる。
3. 企画、設計、仕様、コードの関係が分かる。
4. 確認版と仮プラグインの役割が分かる。
5. 融合、分離、復旧と人間判断の関係が分かる。
6. 親完成条件へ含まれていない。
7. 実データや個人情報が一切含まれていない。
8. Memory Synapse DBの現役正本へ移動できる。

## 10. 現在の停止点

本書は企画の叩き台である。本文の地図化、表現形式、データ、コードは企画と設計の承認後に扱う。

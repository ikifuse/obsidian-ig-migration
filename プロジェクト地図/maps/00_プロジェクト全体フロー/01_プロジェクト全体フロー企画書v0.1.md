# プロジェクト全体フロー企画書 v0.1

## 1. 位置付け

本孫プロジェクトは、七地図の入口となる全体案内を作る。親プロジェクトの内容を一枚ですべて説明するのではなく、発端から現在地、親完成、独立後続までを正しい順序と境界で示し、詳細を確認する地図へ利用者を渡す。

## 2. 必要になった理由

現在の単一地図には、工程の流れ、文書構造、判断理由、横断ルールが同じ画面へ載り、何が時間順で何が説明上の枝なのかを見分けにくい問題がある。

最初に全体の縦軸だけを確認できなければ、詳細地図を開いても現在地と親プロジェクト全体における意味を見失う。そのため、全体フローを七地図の基準座標として独立させる。

## 3. この地図で答える問い

- プロジェクトは何を発端に始まったか
- 企画、設計、仕様、実行はどの順序か
- IGP・IGR・IGSはどこで並列に分岐したか
- 完成済み・凍結、保留、現在作業中をどう区別するか
- IGCと最終パッケージは親完成へどうつながるか
- Memory Synapse DBはどこから独立後続になるか
- 詳細な判断理由はどの地図で確認するか

## 4. 主な利用者

- プロジェクトを思い出したいオーナー
- 初めて全体を確認する人
- 作業開始前に工程と境界を確認するAI

## 5. 表す範囲

- 発端と親企画
- 設計と仕様への受け渡し
- IGP・IGR・IGSの並列工程
- IGXの保留位置
- IGC統合、最終パッケージ、親完成
- Memory Synapse DBへの独立後続
- 各詳細地図への移動

## 6. 表さない範囲

- 各企画判断の詳細説明
- 設計6冊の内部構造
- 仕様の入力・処理・出力条件
- 実コードの構造
- 非公開資料の本文

詳細は対応する孫プロジェクトへ渡し、本フローへ重複掲載しない。

## 7. 表現方針

主軸は上から下へ進む縦型フローチャートとする。工程順の線、並列分岐、状態、責任境界、別プロジェクトへの移行を視覚上で区別する。

装飾よりも、開始点、現在地、次の確認先を短時間で見つけられることを優先する。

## 8. 公開とデータ保護

公開承認済み文書の工程名、状態、役割、判断だけを使用する。個人情報、実データ、非公開判断、ローカルパス、権利未確認素材を使用しない。

## 9. 完成条件

1. 初期表示で開始点と現在地が分かる。
2. 工程順と並列分岐を混同しない。
3. IGP・IGR・IGSの完成済み・凍結状態が分かる。
4. IGXの保留が親完成の必須条件に見えない。
5. IGCから親完成までの残りが分かる。
6. Memory Synapse DBが独立後続だと分かる。
7. 七つの詳細地図へ迷わず移動できる。
8. デスクトップとスマートフォンで主要文字と線を確認できる。

## 10. 現在の停止点

本書は企画の叩き台である。内容と完成条件の確認後に設計へ進み、ノード、線、寸法、技術、コードは設計承認まで作らない。

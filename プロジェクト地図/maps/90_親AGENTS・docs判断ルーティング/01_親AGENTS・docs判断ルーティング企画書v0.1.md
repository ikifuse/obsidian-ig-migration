# 親AGENTS・docs判断ルーティング企画書 v0.1

## 1. 位置付け

本孫プロジェクトは、作業を始める人間またはAIが、作業内容に応じて読むべき文書、適用するルール、必要な承認、停止点へ到達する判断ルーティング図を作る。

親`AGENTS.md`と親`docs/`を置き換える規則集ではなく、正本へ正しく案内する横断地図とする。

## 2. 必要になった理由

親`AGENTS.md`と`docs/`には、企画、設計、仕様、実装、文書配置、恒久ルール変更ごとの読み込み順と停止条件がある。

これを通常の目次として並べるだけでは、「いまの作業なら何を読み、何をしてよく、どこで止まるか」を判断しにくい。目次追加によって単一地図が混乱した経験から、主工程とは別の判断ルーティングとして独立させる。

## 3. この地図で答える問い

- 今回の作業はどの工程に該当するか
- 最初にどのworkflowと目次を読むか
- 追加資料はどんな場合に読むか
- 変更してよい対象はどこまでか
- どの操作に別承認が必要か
- どの時点で停止してオーナーへ確認するか
- 09と10ではどの専用`AGENTS.md`が追加適用されるか
- 非公開資料をどのように扱うか

## 4. 主な利用者

- 作業開始時に確認経路を選びたいオーナー
- 初めてプロジェクトへ参加する人
- 読み込み過多や範囲外変更を避けるAI

## 5. 表す範囲

- 親`AGENTS.md`の工程別読み込みルーター
- 企画、設計、仕様、実装・検証workflow
- 文書配置と恒久ルール変更
- 承認と停止条件
- 09・10の専用ルールへの分岐
- 公開・非公開境界
- 各正本への入口

## 6. 表さない範囲

- 親ルール本文の全文複製
- 各工程の成果物内容
- 非公開資料の本文
- 一時的な作業進捗
- 未承認ルールを確定条件として表示すること

## 7. 表現方針

主軸は判断ルーティング図とする。「何をするか」という入口から、工程、最初に読む文書、追加資料、可能な操作、承認、停止へ分岐する。

規則の詳細は短く要約し、必ず親の正本へ戻れるようにする。単なる文書ツリーや通常のマインドマップにはしない。

## 8. 公開とデータ保護

公開承認済みの規則名、工程名、役割、参照先だけを使用する。非公開資料は存在と境界だけを示し、内容、個人情報、実データ、ローカルパスを掲載しない。

## 9. 完成条件

1. 作業内容から該当工程を選べる。
2. 最初に読む文書を特定できる。
3. 追加資料を読む条件が分かる。
4. 閲覧許可と変更許可を混同しない。
5. 承認が必要な操作と停止点が分かる。
6. 09・10の専用ルールへ正しく分岐できる。
7. 親ルール本文と競合しない。
8. 初めて見る人とAIが同じ正本へ到達できる。

## 10. 現在の停止点

本書は企画の叩き台である。判断条件の詳細化、ルーティングデータ、画面設計、コードは企画と設計の承認後に扱う。

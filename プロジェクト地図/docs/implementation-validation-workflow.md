# 実装・視覚検証工程

## 開始条件

企画書と設計書が承認され、変更対象、実装順、停止点が確定していること。

## 実装原則

- 承認済み設計に記載された地図だけを実装する。
- 親プロジェクトの文書、コード、成果物を変更しない。
- 現行単一地図を公開参考資料として維持し、七地図の完成と切り替えが承認されるまで置き換えない。
- 見た目、操作、データ構造を同時に無制限変更しない。
- 七地図を一つずつ実装・確認し、成立した共通部だけを共有する。

## 視覚検証

各地図について次を実物で確認します。

- 初期表示だけで、地図の目的と中心が分かる
- 主要分岐の文字を無理なく読める
- 展開後も親子、因果、並列、境界を見失わない
- 全体地図へ戻れる
- デスクトップとスマートフォンで操作できる
- 色だけに意味を依存しない
- 文字切れ、ノード重なり、線の誤接続がない
- JavaScriptエラーと読み込み失敗がない
- 公開版でローカル版と同じ内容を確認できる

スクリーンショットと操作結果を使い、画面を見ずに完成判定しません。

## 見た目の完成条件

見た目は、次の機能を果たすまで磨きます。

- 視線をどこから始めるか分かる
- 情報の重要度と階層が分かる
- 地図ごとの役割の違いが分かる
- 長時間見ても混乱しにくい
- 再び開きたいと思える一貫性がある

個人の好みだけによる終わりのない調整は行いません。企画・設計で定めた理解可能性と一貫性を満たし、オーナーが確認した時点を完成とします。

## 公開と停止

- 公開前に、画面、コード、地図データ、素材、メタデータ、エラー表示、リンク先を確認する。
- 個人情報だけでなく、秘密情報、認証情報、非公開判断、実データ、個人を識別できるパス、権利未確認素材、不要な非公開リンクが含まれていないことを確認する。
- Git操作とGitHub Pagesへの公開は、オーナーが対象操作を明示した場合だけ行う。
- 公開後はキャッシュを避けたURLで、地図の表示、展開、移動、エラーを再確認する。
- 七地図すべてが完成条件を満たした結果を報告し、追加機能へ進まず停止する。
